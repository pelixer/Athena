# 아트 아카이브 — 서버 없이 담는 작품 사전

오브제에 **작품 이름과 작가**를 쓰면(없으면 캡션에서 읽은 것) 저절로 맞춰 **작가 · 작업 기간 · 화법(재료·기법) · 화풍(사조·장르) · 근원지(지역)**를
오브제에 메타로 담고, 사진 오른쪽 위에 **꼬리표**(`ArchiveTag`)로 매단다. 누르면 메타 시트(`ArchiveMeta`). 따로 찾는 화면은 없다.
서버·계정·AI 호출 없이, 빌드에 들어간 정적 파일을 앱이 필요한 만큼만 받아 읽는다.

## 오브제에 붙이기 (`src/lib/archiveLink.ts`, `Obje.archive`)
- 입력: `Obje.title` · `Obje.artist`(제목 시트의 "작가 · 선택"), 비어 있으면 캡션 카드의 제목·작가
- 점수 ≥ 0.75(`AUTO_LINK`)면 그 작품을 붙인다(꼬리표에 해). 아니면 비슷한 제목을 후보로 + 작가가 맞았으면 작가 쪽 메타(꼬리표 "?")
- 맞춘 때의 표 줄을 그대로 IndexedDB에 담는다 → 오프라인에서도, 데이터 판이 바뀌어도 그대로 보인다
- 시트에서 후보를 고르면 바꾸고, 메타 떼기를 누르면 같은 입력으로는 다시 붙이지 않는다(`state: off`). 제목·작가를 고치면 다시 맞춘다

## 흐름
1. **수집** — GitHub Actions `archive-data` (손으로 실행: Actions → archive-data → Run workflow → `collect`)
   - `scripts/archive/collect.mjs`: QLever(Wikidata SPARQL, 시간 제한 600초)에 정보 종류마다 질의 → TSV
     (Wikidata Query Service는 60초 제한이라 큰 질의가 504로 끊긴다. 개발 컨테이너는 Wikidata에 닿지 않는다)
   - `scripts/archive/compile.ts`: TSV → 정적 조각
   - 묶음(`athena-archive.tar.gz`)과 원자료(`athena-archive-raw.tar.gz`)를 **GitHub 릴리스** `archive-YYYYMMDD-HHMM`로 올린다
2. **판 고르기** — 레포의 `archive.lock.json` (`tag` · `asset` · `sha256`). 워크플로 끝의 notice에 그대로 적혀 나온다
3. **빌드** — `scripts/copy-archive.mjs`(predev·prebuild)가 릴리스를 받아 해시를 확인하고 `public/archive/<판>/`에 푼다 (`.cache/archive`에 보관, Actions도 캐시)
4. **앱** — `src/lib/archive.ts`가 `/archive/current.json` → 판 폴더의 조각을 받는다. 판 폴더는 1년 immutable 캐시 (오브제 상세를 열 때, 맞출 입력이 바뀌었을 때만)

## 조각 형식 (`src/domain/archive.ts`)
| 파일 | 내용 | 받는 때 |
|---|---|---|
| `manifest.json` | 판 · 개수 | 화면을 열 때 |
| `names/{h0…h18 · a…z · _}.json` | 작가 이름 색인 `[이름, 작가 Qid, 작품 수][]` — 한글은 초성 번호, 이름 전체와 낱말마다 첫 글자 조각에 넣는다 | 작가 이름의 첫 글자들만 |
| `artists/{0…4095}.json` | 작가 묶음 (작가 Qid 번호 % 4096) — 작가와 작품 | 후보 작가의 묶음만 |
| `works/{Qid}.json` | 작품이 400점 넘는 작가의 작품 (작가에 `x: 1`) | 그 작가를 열 때 |
| `vocab.json` | 용어 `{Qid: [한국어, 영어]}` (사조·재료·나라 …) | 처음 찾을 때 |

Cloudflare 정적 자산 한도: 파일 20,000개(무료) · 파일당 25MiB. 묶은 뒤 워크플로 로그에 파일 수와 가장 큰 조각이 찍힌다.

## 맞추기 — 틀리게 써도 (`src/domain/fuzzyName.ts`)
- 한글: 자모로 풀고 헷갈리는 소리를 접는다 — 된소리·거센소리 → 예사소리, ㅑ→ㅏ, ㅐ·ㅖ→ㅔ, ㅕ→ㅓ, ㅛ→ㅗ, ㅠ→ㅜ, ㅢ→ㅣ, 받침 대표음
- 라틴: 악센트 제거 · 소문자 · 겹글자 하나로
- 그다음 편집 거리: 5글자마다 하나까지 고쳐 본다 (짧은 이름은 접은 뒤 같아야 — "모네" ≠ "마네"). 낱말 단위로도 ("뒤쌍"만 써도)
- 작가: 유사도 + 작품 수에 따른 작은 가산 → 상위 4명의 작품에서 제목을 같은 방식으로 맞춘다. 흔한 제목(무제 · 자화상 · 구성)은 영어 제목과 같게
- 받는 조각: 가장 긴 낱말의 첫 글자 조각 하나 (한글은 ㄱ·ㅋ, ㄷ·ㅌ, ㅂ·ㅍ, ㅈ·ㅊ 갈래를 함께)
- 실제 데이터 평가 (2026-10-24, 한국어 이름 있는 작가 1,500명에서 오타 1,124개를 저절로 만들어): 복구 **0.4% → 99.6%**, 정확한 이름 99.9%.
  "마르셀 뒤상 · 마르셸 뒤샹 · 마르세 뒤쌍 · 뒤쌍 → 마르셀 뒤샹", "피까소 → 파블로 피카소", "클로드 모내 → 클로드 모네"
- 해 봤지만 넣지 않은 것: 한국어 이름이 없는 작가를 한글 ↔ 라틴 자음 뼈대로 맞추기 — 맞음 65% · **틀림 30%**. 틀린 연결이 없는 것보다 나빠 뺐다.
  그런 작가는 영어(원어)로 쓰면 된다

## 한계와 다음
- **한국어**: 작가 이름의 6.3%, 작품 제목의 0.5%만 한국어가 있다. 유명 작가·작품은 한국어로 맞지만, 나머지는 원어로 찾아야 한다.
  흔한 제목(무제 · 제목 없음 · 자화상 · 구성)은 영어 제목과 같게 본다.
  보탤 방법: 작품 제목·작가 이름의 한국어 번역·음역을 **Haiku 5.5 일괄 처리**로 한 번 만들어 다른 이름으로 넣기 —
  작가 11.5만 명 이름 음역 약 $0.5, 작품 118만 점 제목 번역 약 $9 (Batch 50% 할인 · 원자료 릴리스에서 바로). Opus는 필요 없다. 사용자 승인 후 진행.
- 영향 관계는 이번 범위에 없다 (Wikidata P737은 드물고 출처가 거의 없다).
