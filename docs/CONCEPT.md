# Athena — 컨셉 노트 (v1 · 2026-10-18)

> 세부 기능·페이지는 미정. 여기에는 지금까지 합의된 컨셉만 기록한다.

## 한 줄 정의
**나만의 미감 저장소.** 미학적으로 영감을 준 것, 아름다운 것을 **오브제**로 담아
`#라벨`과 캡션, 나만의 해석을 붙여 보관하고, 카드와 템플릿으로 남기는 웹앱.

전시와 미술작품이 출발점이자 중심이다(캡션 OCR, 입장권 템플릿, 미술관 같은 화면). 하지만 화면의 말과
유도는 전시에 묶이지 않는다 — 여행지의 빛, 카페의 의자, 거리의 간판, 공연의 한 장면도 같은 방식으로 모은다.
(v0의 "관람"은 v1에서 "컬렉션"으로 넓혔다.)

## 핵심 개념 (용어집 — 디자인과 코드가 같은 이름을 쓴다)

| 용어 | 코드 이름 | 정의 |
|---|---|---|
| 오브제 | `Obje` | 사진 한 장으로 기록되는 대상. 미술작품, 전시, 설치미술, 셀카, 일상의 물건, 날씨 등 무엇이든. 제목(작품명 등)을 가질 수 있다. |
| 라벨 | `Tag` | `#`으로 시작하는 라벨. 오브제에 여러 개 붙는다. (예: `#데이비드호크니` `#다이빙`) |
| 캡션 (옛 이름 도슨트) | `Docent` | 작품 캡션·설명문을 찍은 사진에서 텍스트를 추출(OCR)한 원문. 오브제 옆에 붙는다. 화면에는 "캡션"으로 쓰고 코드 이름은 `Docent`를 유지한다 (2026-10-18). |
| 나의 노트 | `Note` | 나만의 도슨트, 감정, 해석. 오브제에 붙는다. |
| 컬렉션 (옛 이름 관람) | `Visit` | 함께 모은 오브제들의 묶음 — 전시 하나, 여행 하루, 좋아하는 것들의 주제. 이름·장소(선택)·날짜를 가진다. 진행 중이면 "모으는 중". 홈 목록 맨 위에 고정할 수 있다. 코드 이름은 `Visit` 유지. |
| 폴더 | `Folder` | 컬렉션을 묶어 두는 곳. 컬렉션은 폴더 하나에 들어가거나 홈에 바로 있다. 폴더를 지우면 안의 컬렉션은 홈으로 나온다. |
| 순번 | `Visit.index` | 그 컬렉션에서 몇 번째 오브제인지 (찍은 시각 순). |
| 카드 | `Card` (화면 `CardPage`) | 오브제 + 날짜 + 내 해석 등을 얹어 만든 공유용 이미지 (Spotify 가사 공유 카드 같은 형태). 스타일: 하늘 · 대리석 · 사진. |
| 템플릿 | `Template` | 컬렉션 하나를 마무리하며 만드는 **산출물**. 첫 형식은 입장권. |

## 무드
흰 대리석의 표면과 맑은 하늘의 파랑. 사진(오브제)이 주인공이고, UI는 미술관 벽과 작품 라벨처럼 조용하게 물러선다.
디자인 시스템과 대표 화면: `design/source/v0/`

## 원칙
1. **템플릿은 산출물이지 조회의 프레임이 아니다.** 템플릿은 컬렉션을 내보내는 결과물이고,
   오브제·컬렉션을 조회하는 페이지는 템플릿과 무관하게 고유한 화면으로 존재한다.
2. 오브제마다 시간, 위치, 컬렉션 내 순번이 자동으로 기록된다.
3. 기록(사진·캡션)과 해석(나의 노트)은 구분되지만 나란히 놓인다.

## 시나리오 예시
(전시) 국립현대미술관에서 데이비드 호크니의 다이빙 그림을 찍는다 → 옆의 작품 캡션도 찍으면
텍스트가 추출되어 오브제 옆에 붙는다 → 그 자리에서 나의 감정·해석을 적는다 →
전시를 다 보고 나면 나만의 템플릿으로 이 컬렉션을 저장한다 → 마음에 드는 오브제는 카드로 만들어 공유한다.

(일상) 교토 여행 중 "교토의 오후" 컬렉션을 만든다 → 골목의 빛, 찻집의 그릇, 절의 정원을 오브제로 담고
간판·메뉴판도 캡션으로 찍어 둔다 → 돌아와서 "여행" 폴더에 넣고, 가장 아끼는 컬렉션은 홈 맨 위에 고정한다.
